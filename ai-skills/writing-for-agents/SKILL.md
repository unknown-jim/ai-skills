# 写给 Agent 读的文档

skill、`AGENTS.md`、`CLAUDE.md`、项目规则、交给子代理的 prompt——包装方式不同，写法是同一件事。它们的产出不是同一份文本，而是 agent 每次执行时走的**同一个过程**；所以你调的是这个过程的方差，不是句子好不好看。

## 先判断该写在哪

动手写新文件之前，先过这三档，选错档的代价比写得不好大得多：

- **必须每次都生效的规则**（"声称完成前先跑验证"这类）→ 写进常驻规则（本仓库是 `user-preferences`，项目里是 `AGENTS.md` / 项目规则）。**不要做成可发现 skill**：skill 要靠 description 被匹配上才加载，"每次都要"和"匹配才加载"天然打架，做成 skill 就是给自己留一个随机失效的规则。
- **已有 skill 的同主题延伸** → 加一节。新建意味着两个指针要同时维护，而且两条 description 会互相抢触发，哪个都不稳。
- **有明确触发场景、平时不需要占上下文的独立流程** → 才新建 skill。

## 上下文指针

**上下文指针**是留在 agent 上下文里、指向上下文外某份材料的一行：skill 的 description 是指针，`AGENTS.md` 里"某某规范见 docs/x.md"也是指针。

- **触发靠指针的措辞，不靠目标文件写得多好。** 材料再对，指针弱就是不会被加载。该读到的没读到，默认先怀疑指针，而不是急着把材料塞进常驻上下文。
- 指针干两件事：说清材料是什么，以及列出**分支**——这份文档处理哪几种不同情况。
- **首词前置**：最能标识场景的词放最前面，指针的触发工作主要在开头完成。
- **同义词不是分支**：同一个场景换三种说法写三遍，是一个分支写了三次。合并掉，只留真正不同的分支。
- 常驻指针每一轮对话都在收费，所以它比正文更该剪；正文里已经写明的身份和背景，指针里不要再讲一遍。

## 两种负载

- **上下文负载**：常驻材料对模型窗口的成本，触发与否都每轮付。
- **认知负载**：人要记住有哪些文档、什么时候该找哪个。**这个不该一味压低**——它是人保留判断权的价钱，该在需要人判断的地方花，在不需要的地方才去掉。

推到指针后面的材料，用一行指针的代价换掉了它的上下文负载；完全没有指针的材料，全靠人记得它存在。

## 信息阶梯与渐进披露

材料分三层，按 agent 需要它的紧迫程度排：

1. **文件内步骤**——agent 按顺序要做的事，第一优先级。
2. **文件内参考**——按需查的定义、规则、事实。一堆规则平铺在同一层是合理形态，不是坏味道。
3. **指针后的外部材料**——推到另一个文件，指针命中才加载。

**分支测试**决定每块材料落在哪一层：每条分支都要用的内联，只有部分分支才走到的推出去。有步骤的文档里堆太多按需参考，会把步骤埋掉，agent 有没有注意到步骤就变成掷硬币。

**就地聚拢**：一个概念的定义、规则、例外写在同一个标题底下。读到其中一块就顺带把邻居带进来；散落在三个地方的同一件事，读到哪块都不完整。

**篇幅本身也是失败模式**：每行都还有用但总长过头，注意力照样被摊薄，而且每多一行就多一行要维护到不过期。

## 完成判据

每个步骤都要有一个能判定的结束条件。

- **判据要能分辨"做完了"和"还没做完"**。"达成共识""理解清楚了"这种模糊判据会导致**提前收工**：后面的步骤还在视野里，注意力会往"做完"滑。先锐化判据，这是最便宜的修法；判据确实无法锐化、而且你真观察到了抢跑，才用拆分或起子代理把后续步骤挡在视野外——注意只有跨真实上下文边界（交接、独立子代理）才挡得住，同一会话里多加一级标题不清空任何东西。
- **判据的要求强度决定 agent 做多少功课**。"每个改动过的模型都要交代"逼出来的调查量，远大于"给出改动清单"。这跟有没有步骤无关：纯参考型文档用"每条规则都要过一遍"同样能兜住彻底性。

## 引导词

**引导词**是模型预训练里已经有的紧凑概念（红队、烟雾测试、tracer bullet）。反复出现的应该是这个**词**，不是同一段意思的三次改写——重复的词会积累出一个分布式定义，用最少的 token 锚住一整片行为。

- 自造词召回不了任何先验，你要花定义 token 去买现成词免费给你的东西。先找现成的。
- 找那些"一个意思在三个地方各展开一遍"的段落，它们通常都能塌缩成一个词。
- 一个词如果强不过模型的默认行为（对本来就还算仔细的模型说"要仔细"），它就是 no-op。换更强的词，不是换句式。

## 别写禁令

否定式会把被禁的行为拉进上下文，反而抬高它的可得性——"别想大象"之后满脑子都是大象。**写正向目标**，让不该发生的那件事根本不出现在文本里（要"每行一句话的注释"，而不是"不要写长注释"）。

实在没法正向表达的硬护栏才用禁令，而且要配一条正向目标，让注意力落在该做的事上。

## 剪枝

- **单一事实来源**：一个意思只有一个权威位置，改行为是一处编辑。重复不只是浪费 token，还会把这个意思在信息阶梯上的排位抬到超过它实际的重要性。
- **环境也是事实来源**（`package.json` 的 scripts、目录结构、`--help` 输出）。文档复述环境等于做缓存，只有查起来贵的东西才值得缓存：不成文的约定、某个选择背后的理由、配置文件不会承认的坑。一条命令能查到的留给环境，它不会过期。
- **no-op 测试**：这句话相对模型的默认行为改变了什么？答不上来就**整句删掉**，而不是把它改短。判断基准是模型的默认行为，不是读者觉得有没有道理——两个人争一句话算不算 no-op，其实是在争默认行为是什么，跑一遍比争快。
- **沉积**：加内容感觉安全、删内容感觉有风险，所以这类文档的默认结局是层层堆积到得挖开才找得到还活着的部分。剪枝要当定期动作做。

## 改完怎么验

不要读一遍觉得通顺就算数，这类文档的产出是一个过程，得真跑一次，然后按症状分开修：

- **该加载却没加载** → 问题在指针措辞，不在正文。
- **加载了却没照做** → 去找模糊的完成判据、被参考材料埋掉的步骤、写成禁令的那几条。
