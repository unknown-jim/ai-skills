# 派活骨架与共享文档骨架

SKILL.md §2「派活 prompt」、§1 所有权那几条、§0 第 2 件指到这里。凡是会让下游动手的消息——首派、再派、收口打回、CI 红叫回、
启动后扩范围、中途追加一类新操作——都照下面的骨架写。共用段存成模板源，**授权、回报对象、号段逐 chip 填**；订正口径时
先改模板源，再按在飞账本给已派出的 chip 逐个补发。

## 派活骨架

首行：`[派活] <泳道> 号段 <X-D01–X-D09>`；再派写 `[再派·取代 <旧消息的锚>] <泳道> 号段 …`。

1. **坐标**：仓库、集成分支、共享文档路径和等裁决时要回读的那一节、统筹 sessionId（`get_session self` 原样）＋当前标题。
   基线给规则：「以你 rebase 那一刻 fetch 到的 tip 为准，回报写实际值」；要钉死时才给 SHA，并写明它在远端还是只在共享对象库。
2. **范围**：要让用户看到的结果；本期明确不做的。同一个 bug 改多个入口时写「所有到达 X 的调用点（按汇点 grep）」，
   第一条回执先交清单。会被本轮证伪的既有注释和登记行列成交付物，落在别人文件里的列坐标交统筹。
3. **所有权**：见下文「所有权」段。
4. **质量档**：SKILL.md §1.5 定的档；跑 DEA 的写明开哪一步，附统筹列给红队的必查项（本树看不到的跨泳道风险、仓库禁令），
   并写明：「DEA 里凡是写着停下或汇总给用户的出口——撞上停点、Step 0 补过观测仍锁不定根因、下一份读数要真机或用户账号——
   都改成停下报统筹，附最后一次审计的阻塞项、已排除的方向和你建议的下一步；这时等统筹回话，不按第 7 项的默认继续。」
5. **验证判据**：什么读数能证明用户看到的东西变了；点名的变异点和负断言是意图，要你在当前代码里落位、证明在用例路径上；
   断言配负对照（被测逻辑整个不存在时会不会照样绿）。UI 泳道把 `ui-lanes.md`「还原判据」整段贴进来。
6. **前提与已知坑**：见下文「前提」段。
7. **决策路径**：
   - 决策请求写：编号、推荐、证据等级、对推荐不利的读数、选它的代价（列最重那一格）、默认值和何时按默认生效。
   - 可以自决的区间（硬约束＋区间）：区间内自决，回报里报备。
   - 统筹找不到或还没回：把决策点写进共享文档待决表里自己号段的那一行，
     先 commit 与它无关的那一层，按默认继续；猜的地方在源码里标 `[UNVERIFIED]`，写明猜错时会出现什么症状。
   - 稿里读不到的细节写成「你自己定，回报里标出来」；写成「来问我 / 先交用户确认」，chip 弹出的问题卡会落到它自己会话的用户，
     统筹拦不住。
   - chip 是子代理时改写成：「你的最终输出就是回报，找不到统筹是预期」，号段和每个待决的默认在这里给全。
8. **授权**（逐 chip 写）：能不能 push，只引用户原话——本会话里说的，或统筹写进共享文档「用户已定口径」、带日期的那条（写号）；
   没有就写「交付到本地 commit，统筹从共享对象库合」。装机固定写「装机由统筹统一做，你交付到构建成功为止；要真机读数时报统筹排」（SKILL.md「共用机器资源」）。
9. **依赖与接线**：依赖哪条泳道的哪个 SHA、等待期间能做什么；接口谁出、谁接线、什么时候接（接口 commit 先进集成分支，你 rebase 后再接）。
10. **完成回报**——写成动作，和决策路径分开：「完成后给统筹 `<sessionId>` 发一条会话消息，首行 `[完成回报] <分支>@<SHA>`」。字段：
    - 同一回合 `git rev-parse` 原样输出的 SHA（手上只有短的就报短的，发前 `git cat-file -t` 要回 commit）＋「可以合 / 暂不要合」，
      本地还是已推远端；
    - 实际基线；改了哪些既有测试、为什么；变异结果（含存活的几发）；
    - 能声称 / 不能声称什么（数字在终态 SHA 上重取）；范围外的发现、自加的改动和单点回退的办法；
    - 残留逐条标来源：本泳道引入的交付前修掉；既有欠账只报；越界的列给统筹；结构上修不了的说清为什么。「对照今天是严格改善」
      的残差写进「已知退化」，带复现步骤、读数、符号名，写成能独立立项的形态；
    - 已读到的统筹追加项编号；写了哪些记忆文件；泳道状态（待命 / 收工）。
11. **收尾处置**：合入后 worktree、分支、备份分支、会话本身各保留到哪个事件（统筹全量通过 / MR 合入），由谁通知清理；
    要留的验证工具先从会话 scratchpad 搬到持久位置。结项由统筹发一次、下游确认一次。

中途追加一类新操作（构建、发版）时，同一条消息里补上这类操作的已知坑指针。

## chip 开工三步（原样抄进每份派活）

1. `get_session self` 取自己的 sessionId，给统筹发 `[报到] <泳道> <sessionId> <worktree> <分支>`；之后回信一律抄来信的 `from`。
2. 第一条回执先列「与派活前提不一致的读数」（机制、实际在跑的代码路径、引用的旧结论，不只数字）。前提错了但任务形状没变，
   继续做、回报里说明；形状变了、继续只能硬凑，就停在调研，零代码回报。
3. 多步交付每一步结束、push 或交付之前，重读共享文档的裁决区。收到「停下 / 回退 / 你写错了」，先验它是不是给你的
   （拿信里的专有符号数自己 diff 的新增行 `^+`）。

## 所有权

正文 §1 那几条之外，写这一段时还要：

- 用编译单元和符号写，不用「request 相关用例」这种语义描述；测试必要时细到用例。
- 无主文件的默认归属：谁不改它、自己的判据就会假绿，就归谁；拆出去会制造跨泳道依赖的，不拆。几条泳道共同造成的孤儿归统筹，
  泳道只报「能拧到多少 / 可以删了」；公共路径确实要改，统筹单开一条线，附「不传新参数时行为不变」的可杀用例。
- ARB、台账、CHANGELOG 这类多人追加的文件，派活时就分好插入锚点或条目号。
- 禁区按在飞分支实际改到的文件划（`git diff --name-only <base> origin/<branch>`），不按目录 glob 一刀切（一刀切返工过一整轮）。
- **飞地**：挂接点登记在非负责方自己的号段里（符号＋改成什么）；统筹按调用点划归属并附条件（净行数、只动这几处）；
  挂接点在相邻行、仍会文本冲突的，派活时指定由谁解。
- **接口先行**：共享件的最小 commit 过审计后再合入、广播；依赖方不另写一份，不够用写待决。跨所有权的接缝，提供方出公开方法
  并自验语义，接线和「每个入口都接上了」的端到端守护归文件所有者、叠在提供方的 SHA 上做；所有者已经收尾的由统筹接，只在
  合并后才出现、结构上只能在集成分支上做的修补也由统筹做。
- **跨泳道交互点**的联调用例默认由统筹在两条都合入后写，并带变异。
- **派出后所有权一变**：先核实原拥有者没碰过或已收工；授出去的写明只做加法、默认行为不变；同时调整合并顺序。
  接管通知首行：`[接管] <泳道> 新 <sessionId> 接手旧 <sessionId>，所有权 <文件清单>，起点 <分支>@<SHA>`。

## 前提

每条前提标证据等级和出处：`VERIFIED〔出处：命令 / 节点 / 符号 / 读取时刻〕`、`INFERRED〔依据〕` 或 `〔未核〕`。
没亲手读过原文的——转述、记忆、上一轮的结论——一律〔未核〕。

- 零命中、计数、「只有一处 / 不存在」：附产出它的命令和正对照，做一次反向检索；计数写清口径（文件数 / 处数 / 可达数，
  哪棵树、哪个 SHA）。「数过了，但量具错」只有把取数命令贴出来才拦得住。
- 「参照 X / 沿用上次的判据或例外名单」：先读全 X，写出 X 成立依赖的前提、本场景哪里不同。
- 排除式前提（「别再往 X 查」）只在有判别力的证据时才写，并附证据。写之前自检：对立假设成立时这条读数会不会一样？
  量具走没走生产入口？日志是不是两条路径都打？
- 沿用旧专项的结论、或适用面扩大时，按前提逐条重验，并回扫依赖它的裁决。
- 外部 / 上游仓只给 `origin/<branch>` 和读法（先 fetch，再 `git show origin/<branch>:<path>`），不写 SHA、不写没核过的路径；
  下游的结论写 ref＋SHA，引旧 SHA 之前跑 `merge-base --is-ancestor`；长期引用写 ref＋符号名，不写裸行号。
- 稿值标「统筹读稿，下游以稿复核」；手上已有的运行期制品（xlog、时间线、基线失败名单）把路径一起给。
- 固定写一句：「前提与实测冲突以实测为准，按决策路径备案后继续，不必等统筹裁；第一步先试着证伪最关键的那条前提。」

## 共享文档骨架

放在仓库外的固定目录、一次统筹一个目录，泳道按号段写自己的行，统筹写裁决（SKILL.md §0 第 2 件）。在一轮协作之内它是长寿文档，
按 `engineering-discipline`「Long-Lived Plan Documents」管；跨轮是一次性的过程件，下一轮另开一份。
下面的文件头原样放进文档本身——写在文件里的规则，比写在别处的更会被下一个打开它的人照做。

```text
# <主题> 统筹（<日期>；第 N 轮，前几轮：<链接>；仍有效的裁决：<编号>）
不属于这里的：合并流水看 git log --first-parent <集成分支>；长论证放 <附件目录>；派活单放 PROMPT-<泳道>.md。
本文超过 <N> 行就按当前状态重写，不留「已完成」段。一个编号一行、一行一个写方；改判在原行改。

## 0 坐标          仓库 / 集成分支 / 基线规则与当前实际值 / 统筹 sessionId（get_session self 原样）＋标题
## 1 用户已定口径   | 号 | 日期 | 原话 | 性质（期望 / 观察到的现象 / 长期原则） |  照做不问
## 2 号段与在飞账本 | 号段 | 泳道 | sessionId（未点开前先记 task_id） | worktree / 分支 | 状态 | 收到过的裁决 |
## 3 待决表         | 号 | 泳道 | 问题 | 提出者的默认做法 | 裁决（结论＋一句理由） | 状态 | 落地 SHA |
## 4 论证           挂编号，只放表里放不下的
## 5 跨泳道接线须知与共享面   原文，不写「见 X 的完成回报」
## 6 时间窗广播     动了共享环境、或发现它坏了的起止时间和症状
```

写法细则（一条裁决只有一个家）：

- 改判就在待决表原行上改：删除线＋「被 Dxxx 取代」，不在别处另起一条。
- 合并记录写进合并提交的 message（泳道 SHA → 合入点、对应裁决号、验证摘要、授权引的口径号），文档不另抄；派活 prompt
  对会被裁决改写的事实只写编号或节号。
- 写之前重读；裁决追加在请求那一行的末尾。要说「文档里没有 X」，先问写的人是不是正在写。
- 「已写进 X 号」必须对应一次真实写入，发消息前 grep 一次；流程改动先落文档、再发消息。文档里不写「以提交说明为准」。
- 口径表每条标来源（用户 / 稿 / 统筹推荐 / 下游默认），只有用户定的锁定给用户；用户当场新拍板的写回第 1 节，裁决理由引口径号。
- 号段：统筹自留一段；泳道代号不用和编号前缀相同的字母，号段带泳道前缀（X-D01 / Y-D20）；红队、审计、交付物、待办各用
  不重叠的前缀；中途新开的泳道当场登记，新变更流从原号段切子段；号段用完向统筹申请，用不掉的要对方明说「一个没用」才收回。
- 被撤换的会话在第 2 节登记作废。坐标、名册、号段随变化当场改；收口前扫第 3 节的「待 / 待统筹」，非空就是漏裁。
- 决定长期行为的前提和限定，落成能执行或能长期留存的东西（守卫用例、门禁断言、代码注释、报错文案、可重跑的枚举命令）；
  本文是一次性的过程件，多轮协作每轮开一份新的。
