# 设计稿与迁移类泳道

SKILL.md §1 清单轮、§2 验证判据、第 4 节第 1 步指到这里：按设计稿改版、做组件或接口迁移的泳道用。

## 清单怎么取

- **差异清单从画出来的节点取，不从批注和设计答复取**：逐个状态画板读节点属性（尺寸、圆角、内边距、填充、描边、阴影、
  图标尺寸），对照代码现值，不一致的每一处都进清单。「本次优化」列表、批注、设计对问题的答复只记了设计**想到要说**的那部分，
  画出来但没写字的改动（圆角 24→32）永远不会出现在里面。2026-09-22 输入框改版正是这样锁的范围：单行态、语音态的圆角
  漏掉了，被用户一眼看出来；「按住说话改单行」也是读稿时碰巧撞见才补进来的。
- 同一个文件里常有没跟着更新的**旧组件实例**（那次两张画板还挂着旧组件，圆角 24，与代码一致）：以主流程画板上的新组件为准，
  旧画板列成稿面矛盾交给设计。
- **数值连它所在的那一层一起读**：clipsContent 容器里越界的偏移本身有含义；四角不等时圆角读出来是 mixed，不是 0；旁注挂在
  哪个框上，决定它管哪些元素；有变量绑定就读变量，不读静态字段；画板上没画的状态，去组件的变体集里找。
- **按「是否渲染」判断元素在不在**：核 `visible`、fills / strokes 是否为空、组件集里的其它变体，或者直接对照导出图；
  图层名不等于渲染结果。泳道对稿面的自行判断（「稿上没有」），统筹用导出图核实。
- 稿是活文档：读数带读取时刻，交付前重读一遍。派活里的稿值标「统筹读稿，下游以稿复核」。
- 实现者自己定的值内联在使用点，标「非设计标注」，不进 token——并排放进 token 文件，会被下一个人当成设计值读。
- **覆盖表**：按文件切完泳道后，再出一张「画板 / 状态 → 泳道（或本期不做）」覆盖表，没有归属的画板列出来问用户。

## 还原判据

画 UI 的泳道，派活时就把这段写进验证判据，不等用户提醒：

- 逐节点差异清单（含画出来没写字的值）；
- 每个负责状态的 golden 与稿截图并排比对；
- **亮 / 暗两色各一张，并单列暗色覆盖表**；
- 分级报 FUNCTION / VISUAL / DESIGN_VERIFIED。

只写「按稿实现」，下游会只交亮色、只比结构（2026-09-29：派完才被用户先后提醒「注意还原设计稿细节」
「别忘了适配暗色模式」，回头一查各线暗色只做了零星几张）。

## 回执里的稿差

泳道报上来的稿差先按范围分流：范围内的按稿返工；「按推荐落地、设计提 issue 再改」只用于稿面没说或自相矛盾的地方。

## 组件 / 接口迁移

- 清单轮在视觉差异之外加一列「行为对等」：键盘避让、焦点、安全区、手势关闭、路由名 / 埋点、返回与关闭的时序。可以先做一次
  替换探针，拿消费方既有测试变红的地方收集缺口。
- 默认口径：形态和视觉按目标走；既有调用方的行为、承载信息的元素保持不变；纯装饰按目标丢掉（「禁用是行为不是视觉」
  「勾是选中态信息，丢掉是信息回归」）。用户对某个行为的明确要求是行为契约，优先于通用样式。
- 缺的 API 由组件 owner 放在最前面的提交里落地，依赖方分批做。同一个缺口两条以上泳道都撞上，就到共享组件的根上修，删掉
  业务侧的绕行，各调用方回到自己的调用点复跑（底部弹层组件没透传键盘避让参数，是迁移新引入的回归，2026-09-23）。
